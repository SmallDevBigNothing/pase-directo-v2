## 2026-07-04 - [CRITICAL] Fix Cross-Site Scripting (XSS) in Admin Dashboard
**Vulnerability:** A Cross-Site Scripting (XSS) vulnerability existed in the Admin Dashboard, specifically in the "Edit Match" button rendering logic (`loadMatch` onclick handler in `server.js`). The code dynamically constructed an object by injecting match properties directly into a template literal without proper escaping. A malicious user with scraping/API access (e.g. creating matches with `\x3cscript\x3e` in the `local`, `visitante` or `competicion` fields) or an admin manipulating data could have successfully executed arbitrary JavaScript within the context of any admin visiting the dashboard, leading to session hijacking or full admin takeover.
**Learning:** Due to the app using raw string concatenation instead of a template engine or a frontend framework (like React or Vue) for server-side rendering, variables passed directly into HTML attributes (especially event handlers like `onclick`) must be rigorously escaped. The original implementation attempted a manual escape using `.replace(/`/g, '\\`')` on fields stringified in a template literal, but it was insufficient. It did not properly escape single quotes, double quotes, or HTML entities, which allowed breaking out of the event handler attribute context and executing arbitrary XSS payloads.
**Prevention:** When injecting complex objects or variables into raw HTML string attributes in JavaScript, always use `JSON.stringify()` to safely serialize the object to a valid JSON string, and then explicitly escape HTML entities (e.g., using `escapeHtml()`) before placing it within the HTML attribute. Example: `onclick="loadMatch(${escapeHtml(JSON.stringify(matchObject))})"`.
